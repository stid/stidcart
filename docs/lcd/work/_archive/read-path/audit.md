## Read this before trusting the PASS

**The gate is vacuous for this work-item.** `audit-crosspath.sh` skips every `none` surface
(`[[ "$surface" == "none" ]] && continue`), and all twelve acceptance criteria here are
`surfaces: none`, because the read path is a library capability that deliberately exposes no
command-line surface. So the script had nothing to check and passed by having nothing to fail on.

This is expected rather than a defect — the audit exists to catch the same behaviour diverging
across two parallel surfaces, and there are not two surfaces here. It is recorded loudly because
"audit: PASS" in the closeout line would otherwise read as "coverage verified", which it is not.

The write-path item's audit hit the opposite problem: its BLOCK came from its **CLI** rows, not its
`none` ones, and its own report says the `none` criteria sit "outside the cross-path contract". The
degenerate matrix in this item's `plan.md` was originally justified by that precedent; the
justification was wrong and has been corrected in place.

## What actually gates this work-item

1. **The round trip** (AC-2, AC-4, AC-11). Load then rebuild is byte-identical across all four
   frozen fixtures and the empty base case. This is the real oracle: it makes the read path and the
   write path check each other rather than both being checked against one reading of the format.
2. **T-final** — `cargo fmt --all --check && cargo clippy … -D warnings && cargo test --workspace`.
   97 tests, 0 failures, fmt and clippy clean.
3. **Two negative controls**, because every AC passing on the first run is weak evidence on its own,
   and one control only proves the path it touches:
   - Decoding the container header name with the machine's character swap makes AC-8 and AC-9 fail
     immediately — the exact conflation D-006 exists to prevent.
   - Returning the loaded entries in reverse order makes AC-2 fail on `two.crt` (`18 bytes differ;
     first at 0x2060`). That is the one that matters: the first control only exercises the header,
     so without this one "load then rebuild is byte-identical" could have been true without being
     load-bearing for entry recovery or placement. It is.
