### Cargo-specific notes on the test keys

- **`{path}` is the test-target stem, not a filesystem path.** `cargo test --test` takes a *target
  name* — the `tests/<stem>.rs` filename without its extension — so `{path}` = `directory`, not
  `crates/stidcart-core/tests/directory.rs`. Every target stem in this workspace is currently
  unique across both crates (`container` `directory` `parity` `placement` `read` `reserved`
  `roundtrip` in core; `boot` `cli` `list` in cli), so `--workspace --test <stem>` resolves without
  a `-p`. Add `-p stidcart-core` / `-p stidcart-cli` if that ever stops being true.
- **There is no true per-test bail.** libtest has no `--bail`; `cargo test` fails fast at *target*
  granularity (it stops before the next target once one fails) and runs every test inside a target.
  `bail` therefore names a single target, which is the tightest loop cargo offers. `--no-fail-fast`
  is the opposite flag — never add it to these keys.
- **Nothing here watches.** Cargo has no watch mode without `cargo-watch`, so the red-green loop
  cannot hang on these commands.
- **`single-test` filters by substring** on the test function name. Append `-- --exact` only when
  you have the fully-qualified name and a substring would over-match.
- **Existing `ac_N_*` tests are orphans, and their doc comments DO carry the audit's token.**
  `ac_2_every_reference_image_loads…`, `ac_4_…`, `ac_9_…`, `ac_11_…` and friends are left over from
  the pre-D-013 pipeline; the specs that numbered them were deleted, so those ids reference nothing.
  An earlier version of this note claimed they could not false-green a coverage check because the
  old *function names* lack the literal `AC-N (SURFACE)`. That was wrong: the audit greps comments,
  and the orphans' doc comments carry the tokens verbatim — `grep -rn "AC-[0-9]* (" crates/` lists
  them. A new work-item reusing a live number would pass the test-presence check against somebody
  else's test.
- **Therefore: number a new work-item's ACs from the next free id, not from AC-1.** The tokens in
  use are `AC-1..AC-12 (none)` and `AC-1..AC-5 (CLI)`, plus `AC-13..AC-16 (…)` taken by
  `easyfs1-refusal`, plus `AC-17..AC-30` taken by `cart-edit`, plus `AC-31..AC-46` taken by
  `cart-entries`. **Next free: AC-47.** Bump this line
  when a work-item claims a range. Renaming
  the orphans instead would be a sweep across six files for no behaviour change — rename them only
  if you are already editing the file.
- **`test-placement`**: `<area>` is `core` or `cli`. Inline `#[cfg(test)]` modules next to the code
  are equally valid and equally collected — prefer them for unit-level assertions on a private
  function, and `tests/<slug>.rs` for anything that drives the public API or the binary.

## Constitution notes

> Constraints a Deep-lane `plan.md` Constitution check and the red-green loop must honor.
>
> **The project's invariants are not copied here.** The bundled template restates them so they
> survive on a fresh clone, which is the right default when they live in a maintainer's global
> rules — but this project's invariants live in `docs/lcd/MAP.md`, which *is* in the clone. A second
> copy would go stale the first time one is edited on one side only, and D-015 just spent this
> branch removing exactly that kind of duplicate.

- **Honor every invariant in the `Invariants` section of `docs/lcd/MAP.md`** — byte parity against the
  fixtures, the decaying oracle, `docs/format/` as the source of format facts, the zlib/GPL boundary at
  `firmware/`, no global state or I/O policy in the core, the crate version reaching produced bytes,
  describing versus rebuilding (D-011), and per-behaviour read-path divergence (D-007). Read that
  section, not a paraphrase of it.

The rest are process constraints from `CLAUDE.md` with no home in the MAP:

- **The toolchain is pinned by `rust-toolchain.toml`** (D-010) and the pin binds only through
  rustup's shims — a Homebrew `cargo` ignores the file silently. Verify with `cargo --version`
  before trusting a green or red gate.
- **Never commit to `main`.** Branch, PR, conventional commits. Required checks: `gate` and
  `claude-review`.
- **Tests first**, and the gate above is green before every commit.
