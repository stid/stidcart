# Fixtures

Reference cartridge images produced by `ndeft` (ndefpack 1.0.1), frozen here so the byte-parity
check keeps working after that tool is gone. Nothing in the test suite invokes `ndeft`.

Every reference image (`*.crt` not starting `in_`) carries the firmware `ndeft` embeds: EAPI, the
boot code and the EasyLoader menu. Those regions are zlib-licensed, by Thomas 'skoe' Giesel and
ALeX Kazik with Hannu Nuotio's changes; see `../firmware/README.md`. The inputs below are
synthetic and contain nobody else's code.

Captured **2026-08-10** with `ndeft` built from a locally patched copy of ndefpack 1.0.1 (not
published), run from inside this directory so the derived entry names are bare file stems.

## Inputs

Generated deterministically; each is a `.prg` loading at `$0801` with a byte ramp as its body.

| File | Body bytes | Formula |
|---|---|---|
| `hello.prg` | 100 | `(i * 7 + 3) % 251` |
| `ramp.prg` | 3000 | `(i * 7 + 11) % 251` |
| `big.prg` | 20000 | `(i * 7 + 29) % 251` |

`big.prg` is deliberately larger than one 8 KB bank, so it exercises the interleaved continuation.

## Reference images

| Image | Exact request | Covers |
|---|---|---|
| `single.crt` | `ndeft -q -o single.crt build hello.prg` | no cartridge name given — the placeholder path |
| `named.crt` | `ndeft -q -e "weird name" -o named.crt build hello.prg` | cartridge name stored in the flash region |
| `two.crt` | `ndeft -q -e "two entries" -o two.crt build hello.prg ramp.prg` | two entries, placed largest-first while the directory keeps input order |
| `spill.crt` | `ndeft -q -e "spill" -o spill.crt build big.prg` | an entry continuing across bank halves |

## Reproducing (original images)

```bash
cd fixtures
ndeft -q -o single.crt build hello.prg
ndeft -q -e "weird name" -o named.crt build hello.prg
ndeft -q -e "two entries" -o two.crt build hello.prg ramp.prg
ndeft -q -e "spill" -o spill.crt build big.prg
```

## Cartridge-entry fixtures (cart-entries work-item)

Captured **2026-09-19** with `ndeft` built from the same copy two commits later (both confined
to a placement diagnostic and a read-side bounds fix; produced bytes for valid input are
unchanged). Run from inside this directory, as above.

### Cartridge inputs

Synthetic, generated by `make_inputs.py` (run it from inside `fixtures/`; the output is
byte-identical every time). Each image's CRT header name is its file stem, so the menu name
`ndeft` derives from a cartridge input equals the stem this tool derives from the file name. Bank
body byte `i` of file `k` (its index in the script's table), bank `b`, half `h` is
`(i * 7 + 3 + 5*k + 2*b + h) % 251`.

| File | CRT id | EXROM/GAME | Packets |
|---|---|---|---|
| `in_8k.crt` | 0 | 0/1 (8k) | one `0x2000` at `$8000`, bank 0 |
| `in_16k.crt` | 0 | 0/0 (16k) | one `0x4000` at `$8000`, bank 0 |
| `in_ult8.crt` | 0 | 1/0 (Ultimax) | one `0x2000` at `$E000`, bank 0 |
| `in_ult16.crt` | 0 | 1/0 (Ultimax) | `0x2000` at `$8000` then `0x2000` at `$E000`, bank 0 |
| `in_ocean.crt` | 5 | 0/0 | banks 0–15 at `$8000`, banks 16–31 at `$A000` (256 KiB) |
| `in_ocean512.crt` | 5 | 0/1 | banks 0–63 at `$8000` (512 KiB) |
| `in_xb8.crt` | 33 | 0/1 (8k) | banks 0–3 at `$8000` |
| `in_xb16.crt` | 33 | 0/0 (16k) | banks 0–3 at `$8000` and `$A000` |
| `in_xbult.crt` | 33 | 1/0 (Ultimax) | banks 0–1 at `$8000` and `$E000` |
| `in_xbwide.crt` | 33 | 0/0 (16k) | banks 0–39 at `$8000` and `$A000` (640 KiB — past the reference tool's entry cap, D-022) |

| `cult16.crt` | `ndeft -q -e "cult16" -o cult16.crt build hello.prg in_ult16.crt` | an Ultimax 16k cart, ROMH primary with a ROML run at offset 0 |
| `cocean.crt` | `ndeft -q -e "cocean" -o cocean.crt build big.prg in_ocean.crt` | Ocean mode: the cart at bank 0, ROMH run at +16, loader at bank 1 ROMH; the program fills the ROML gap at bank 16 |
| `cocean512.crt` | `ndeft -q -e "cocean512" -o cocean512.crt build hello.prg in_ocean512.crt` | Ocean 512k filling every ROML bank; the program goes to the ROMH gap at bank 2 |
| `cxb16.crt` | `ndeft -q -e "cxb16" -o cxb16.crt build hello.prg in_xb16.crt` | an xbank 16k cart, four banks in both halves |
| `cxb16a.crt` | `ndeft -q -e "cxb16a" -o cxb16a.crt build "in_xb16.crt,aligned,a" hello.prg ramp.prg` | 64 KB alignment puts the xbank at bank 8; both programs fill the ROML gap below it, largest first |
| `cxbult.crt` | `ndeft -q -e "cxbult" -o cxbult.crt build hello.prg in_xbult.crt` | an xbank Ultimax cart, ROMH primary |
| `cmixed.crt` | `ndeft -q -e "cmixed" -o cmixed.crt build in_8k.crt in_16k.crt in_ult16.crt in_xb8.crt hello.prg ramp.prg big.prg` | the full ordering: carts by weight (xbank first, then the two 16k-tall carts in input order, then the 8k), programs into the ROMH gap left by the 8k-mode xbank |
| `cxbwide.crt` | `ndeft -q -e "cxbwide" -o cxbwide.crt build in_xbwide.crt hello.prg` | **the reference tool wrote this image and cannot read it back** (`ndeft list` fails with `size $0a0000 > $80000`). It pins the write side of D-022 only; the read side has no oracle |

## Subdirectory-bit fixtures (subdir-entries work-item)

Captured **2026-10-11** with that same later build of `ndeft`, run from inside this
directory.

`ndeft` carries the CrtUsage subdirectory bit (`0x4000`) on an xbank entry but no request of its own
sets it, so the input is a reference image with the bit patched in. `make_inputs.py` writes it
(its `PATCHED` table), after the synthetic inputs above.

| File | Made from | Patch |
|---|---|---|
| `in_cxb16sub.crt` | `cxb16.crt` | slot 1 (`in_xb16`, xbank 16k): CrtUsage `0x8004` → `0xc004` (bit `0x4000` set) |

| Image | Exact request | Covers |
|---|---|---|
| `cxb16sub.crt` | `cp in_cxb16sub.crt cxb16sub.crt && ndeft -q ren cxb16sub.crt 0 hello2` | the reference re-saving a cart with a subdirectory-flagged xbank: only the name byte changes, so the bit is carried |

## Two things that will bite

- **`-e` is not the container header name.** It sets the cartridge name inside the flash image at
  `0x81b08`. The 32-byte name at offset `0x20` of the `.crt` always reads `ndefpack 1.0.1`, from
  `PACKAGE_STRING`. The parity test pins that string explicitly; see D-006.
- **Never boot a fixture in VICE.** `x64sc` defaults to `-easyflashcrtwrite` and saves the emulated
  flash back over the image on exit, stamping its own name into the header. Boot a copy, or pass
  `+easyflashcrtwrite`.
